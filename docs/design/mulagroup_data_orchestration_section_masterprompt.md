# Mula Group Data Orchestration Section Master Prompt

## Purpose

This document contains a refined Codex master prompt for building or improving a premium animated **data orchestration map** section inside the Mula Group portal.

This prompt is **not** for a radial node tree.
It is for a higher-trust, more architectural **systems map** that shows:

- one integration hub,
- multiple connected business domains,
- layered data movement,
- orchestration logic,
- intelligence flow,
- reporting flow,
- calm premium motion.

It should help Codex build a section that feels like a real operating-system blueprint for a company, not a generic infographic.

---

# Copy This Prompt Into Codex

```text
You are acting as a senior front-end architect, motion UI engineer and premium systems-visualization designer.

Your task is to implement or improve a **production-ready animated company data orchestration map section** inside the Mula Group website.

This is NOT a radial integration tree.
This is NOT a generic node graph.
This is NOT a dashboard screenshot.

You must build a premium, readable, animated, responsive **orchestration map** that communicates how Mula Group can connect a full company operating system through one integration layer.

The section must feel:
- premium
- architectural
- calm
- intelligent
- high-trust
- technically credible
- visually controlled

It must NOT feel:
- cluttered
- cyberpunk
- noisy
- gimmicky
- like startup concept art
- like a random force-directed graph

--------------------------------------------------
PRIMARY GOAL
--------------------------------------------------

Build a reusable animated section component that shows:

- one Integration Hub
- ten connected business domains
- visible orchestration pathways
- visible data-sync relationships
- visible intelligence and insight pathways
- staged reveal animation
- subtle living-state pulses after reveal

The section should make the visitor feel:

"Mula Group can connect the company across marketing, sales, support, commerce, logistics, finance, ERP, operations, AI and reporting as one controlled business system."

--------------------------------------------------
SECTION CONTENT
--------------------------------------------------

Use the following structure:

### Section title
Use:
Integrated Data & Workflow Orchestration in Practice

### Supporting paragraph
Use:
This map shows how Mula Group can connect acquisition, sales, customer service, operations, logistics, finance, ERP, AI and reporting into one controlled orchestration layer.

### Supporting line under animation
Use:
One orchestration hub. Ten synchronized business domains. One decision-ready data stream.

### CTA heading
Use:
Want this kind of data orchestration in your company?

### CTA button
Use:
Book a strategy conversation

You may refine wording slightly for design polish, but preserve meaning.

--------------------------------------------------
MAP CONCEPT
--------------------------------------------------

The visual should not be organized as a circular diagram.

Instead, use a **systems-map composition**:

- one Integration Hub placed in a strategic anchor position
- domain nodes distributed across the wider canvas
- many connections routed intentionally through readable lanes
- a sense of flow across the whole operating system
- labels like orchestration, data sync, intelligence layer, customer journey, insights where useful

The map should feel like:
- an operating architecture board
- a business systems blueprint
- an orchestration layer visual

It should not feel like:
- abstract geometry for its own sake
- a decorative network
- a chart with no narrative

--------------------------------------------------
CORE STRUCTURE
--------------------------------------------------

### Primary integration hub
- Integration Hub

### Connected domains
1. Marketing & Acquisition
2. Sales & CRM
3. Commerce & Orders
4. Customer Service
5. Operations & Workflow
6. Logistics & Fulfillment
7. Finance & Accounting
8. ERP & Warehouse
9. AI & Automation
10. Reporting & Management

--------------------------------------------------
DOMAIN DETAIL
--------------------------------------------------

Each domain should imply meaningful operational depth.

You may use compact domain detail internally or via tooltips/micro lists if the implementation supports it, but the primary canvas should stay readable.

Suggested domain logic:

### Marketing & Acquisition
- forms
- campaigns
- lead capture
- social capture
- website

### Sales & CRM
- CRM pipeline
- lead scoring
- AI triage
- follow-up logic
- opportunity handling

### Commerce & Orders
- orders
- pricing logic
- marketplace sync
- payment status
- order history

### Customer Service
- ticketing
- SLA
- complaints
- returns
- customer timeline

### Operations & Workflow
- task routing
- approvals
- document flow
- delivery workflow
- operating status

### Logistics & Fulfillment
- courier sync
- labels
- tracking sync
- dispatch workflow
- delivery proof

### Finance & Accounting
- invoicing
- reconciliation
- accounting sync
- margin control
- finance dashboard

### ERP & Warehouse
- stock levels
- SKU logic
- warehouse movement
- reorder logic
- ERP reporting feed

### AI & Automation
- AI summaries
- routing logic
- automation triggers
- anomaly detection
- decision support

### Reporting & Management
- owner view
- weekly summary
- monthly review
- KPI board
- management summary

--------------------------------------------------
LAYOUT STRATEGY
--------------------------------------------------

Use a **deterministic systems-map layout**, not a radial tree.

The map should be built using:
- fixed node positions
- clear route channels
- grouped connection corridors
- intentional asymmetry
- controlled negative space

Recommended composition:

- Integration Hub near upper-left or upper-central zone
- commercial / acquisition systems on the left side
- execution / operations systems on the right side
- ERP / AI / reporting / finance forming the lower system layer
- support bridging customer and operations layers

The user should feel that the system has:
- a front-office layer
- an execution layer
- a control / intelligence layer
- a reporting / management layer

--------------------------------------------------
SPATIAL RULES
--------------------------------------------------

- nodes must never overlap
- labels must remain readable
- line bundles should share lanes where possible
- major domains should have stronger presence than annotations
- the hub should be clearly identifiable as the control point
- the map should feel busy in intelligence, but never messy in layout

Do NOT place nodes randomly.
Do NOT rely on manual luck.
Use a real geometry system.

--------------------------------------------------
LINE / FLOW RULES
--------------------------------------------------

Connections should represent:

- orchestration
- customer journey
- data sync
- intelligence layer
- insights

Use different visual strengths, but keep all of them elegant and thin.

Rules:
- primary orchestration routes should be strongest
- supporting sync routes should be lighter
- intelligence / insight routes should be subtle
- avoid visual spaghetti
- where useful, bundle routes before splitting

Cross-links should improve understanding, not show every possible relationship.

--------------------------------------------------
VISUAL HIERARCHY
--------------------------------------------------

Hierarchy must be obvious:

1. Integration Hub
2. major domain nodes
3. connection routes
4. small annotations / route labels

Make sure:
- hub has the strongest visual treatment
- domain nodes are color-distinct but still premium
- route labels are subtle, not shouting
- the canvas breathes

--------------------------------------------------
MOTION BLUEPRINT
--------------------------------------------------

Use staged reveal motion.

### Scene 0 - ambient start
- faint grid
- soft background
- low-contrast route skeleton hidden
- subtle hub glow only

### Scene 1 - hub activation
- Integration Hub fades in
- scale 0.9 to 1
- single calm pulse

### Scene 2 - first connected domains
Reveal:
- Marketing & Acquisition
- Sales & CRM
- Commerce & Orders
- Operations & Workflow

### Scene 3 - second domain layer
Reveal:
- Customer Service
- Logistics & Fulfillment
- Finance & Accounting
- ERP & Warehouse
- AI & Automation
- Reporting & Management

### Scene 4 - route reveal
- orchestration routes draw in
- then data sync routes
- then intelligence / insights routes

### Scene 5 - living state
- subtle signal pulses move along selected routes
- hub glows gently
- a few active paths breathe softly
- final state must remain calm

Do NOT make the final state noisy.

--------------------------------------------------
TECH STACK
--------------------------------------------------

Preferred implementation:
- React
- SVG for map rendering
- Framer Motion for line reveal and signal pulses

Use:
- pathLength for route drawing
- opacity + scale for node reveal
- small signal pulses on key routes
- deterministic geometry

Keep code:
- modular
- typed
- reusable
- data-driven
- maintainable

--------------------------------------------------
COMPONENT STRUCTURE
--------------------------------------------------

Recommended breakdown:
- DataFlowOrchestrationSection
- OrchestrationMapCanvas
- OrchestrationNode
- OrchestrationEdgeLayer
- OrchestrationHintLayer
- OrchestrationPulseLayer
- OrchestrationCompactLayout

Recommended data model:
- node id
- node label
- node position
- node tone
- node shape
- edge source
- edge target
- anchor points
- route bend value
- edge type
- pulse flag
- route label hints

--------------------------------------------------
TEXT RULES
--------------------------------------------------

- keep node labels short
- use 1-2 lines max inside major nodes
- avoid giant pills caused by long wording
- route labels should be minimal and strategic
- annotations should support the map, not dominate it

--------------------------------------------------
RESPONSIVE RULES
--------------------------------------------------

Desktop:
- full orchestration map
- many visible routes
- refined layered geometry

Tablet:
- simplified orchestration board
- fewer visible route labels
- preserved main system logic

Mobile:
- do NOT compress desktop map
- use grouped domain cards or simplified orchestration summary
- preserve the message:
  one integration hub, many connected business systems, one controlled flow

The mobile version must feel intentionally designed, not reduced by force.

--------------------------------------------------
PERFORMANCE RULES
--------------------------------------------------

- avoid excessive DOM clutter
- keep route geometry deterministic
- avoid particle spam
- animate only meaningful elements
- minimize infinite loops
- use a small number of pulse signals

--------------------------------------------------
PAGE INTEGRATION
--------------------------------------------------

Insert the section as a premium proof-of-capability block in the main portal.

It should feel like:
- a strategic reveal
- a system proof moment
- a high-trust technical explanation

Spacing before and after the section must feel intentional and premium.

--------------------------------------------------
IMPORTANT RULES
--------------------------------------------------

- do not redesign the whole page
- do not turn this into a radial tree
- do not turn this into a generic infographic
- do not allow overlapping nodes or messy route clutter
- do not make motion louder than the brand
- preserve the premium Mula Group visual language

--------------------------------------------------
DELIVERABLES
--------------------------------------------------

When finished, return:

1. summary of what was built
2. component structure created
3. layout strategy used
4. motion approach used
5. responsive behavior implemented
6. simplifications made for readability or performance
7. where the section was inserted

After implementation, immediately run a refinement pass:
- overlap check
- route clutter check
- node alignment check
- mobile simplification check
- production QA

Now implement the full premium animated data orchestration map section.
```

---

## Implementation Note

Use this prompt when the target visual is:

- an orchestration board,
- a systems map,
- a controlled operating architecture diagram,

and **not** when the target visual is:

- a radial integration tree,
- a circular sector map,
- a node cloud around a central core.

If the section already exists, this prompt should be used for **refinement**, not blind reimplementation.
